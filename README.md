A small Windows desktop app to identify what your mouse buttons actually send and keep a personal World of Warcraft binding plan.

## Use it

Open **WOW-Mouse-Mapper.exe** from the portable Windows x64 build. No installation or administrator access is required. Portable builds include the .NET runtime; source builds require the .NET 10 SDK.

1. Click **Start testing** and move your pointer into the mouse test area.
2. Press a mouse button or scroll. Hold **Ctrl**, **Shift**, or **Alt** to check combinations. Buttons that send keyboard keys are also recognized.
3. Press **Esc** or click **Stop testing**. The last input stays visible.
4. Name the physical button (for example, “rear thumb button”), optionally enter its WoW action, and click **Save binding**.
5. Open WoW's key bindings, choose your action, and press the same physical button there.

Double-click a saved row to edit it. **New binding** clears the editor. **Export** saves a JSON backup or CSV reference sheet; **Import** restores a JSON backup after confirming replacement of the current list.

## What the signals mean

| Signal | Meaning |
| --- | --- |
| BUTTON1 / BUTTON2 | Left / right mouse button |
| BUTTON3 | Wheel click |
| BUTTON4 / BUTTON5 | Standard side-button inputs (X1 / X2) |
| MOUSEWHEELUP / MOUSEWHEELDOWN | Vertical wheel |
| WHEELLEFT / WHEELRIGHT | Horizontal wheel; check support in your game |
| 1, NUMPAD1, F13, etc. | A keyboard signal emitted by your mouse or keyboard |

The mouse drawing is a generic reference, not a hardware scan. Side-button positions vary by model. MMO mice with more than five buttons often expose their extra buttons as keyboard keys. Windows keyboard messages cannot tell this app whether a key originated on your keyboard or was generated by mouse software. The recent-input line helps reveal multi-key macros; a saved binding contains only the last input, not a macro recording.

If a button produces nothing, check your mouse software. DPI, onboard profile switches, and proprietary HID/media controls may not emit supported signals. Assign an ordinary spare keyboard key in the mouse software and test again. Desktop and game-specific mouse profiles may differ. Number-pad behavior depends on Num Lock. Some keys, horizontal-wheel signals, and left/right mouse combinations may be reserved or unsupported by WoW.

This is an **input tester and binding planner**. It does not reprogram hardware, change WoW settings, inject input, or run macros. Escape is reserved for stopping the test. System shortcuts such as Alt+Tab remain subject to Windows behavior.

## Privacy and saved data

Input capture is active only after you start a test, while the app is in the foreground. Switching windows pauses it. Mouse events are accepted only inside the test area. No background keyboard hook, game integration, telemetry, or network service is used. Keyboard signals from both the keyboard and mouse software appear during testing. Only explicitly saved bindings are persisted; recent inputs stay in memory.

Bindings are stored at `%LOCALAPPDATA%\WOW-Mouse-Mapper\bindings.json`. Writes use a temporary file and replacement. If the existing file cannot be read, it is preserved and saving is blocked; back up and repair or rename the file, then restart the app. JSON imports are validated before any existing data is replaced.

## Build and test

Windows 10/11 x64 and the .NET 10 SDK:

```powershell
dotnet build src/WowMouseMapper/WowMouseMapper.csproj -c Release
dotnet run --project tests/WowMouseMapper.Tests.csproj -c Release
dotnet run --project src/WowMouseMapper/WowMouseMapper.csproj
```

Create a standalone executable:

```powershell
dotnet publish src/WowMouseMapper/WowMouseMapper.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -o artifacts/win-x64
```

GitHub Actions runs the tests and uploads a portable build on pushes and pull requests. Download it from the completed run's **Artifacts** section. No third-party NuGet packages are required.

For isolated manual testing, launch the app with `--data-dir "C:\path\to\test-data"`. Test left/right/middle/side clicks, all wheel directions supported by your mouse, modifier combinations, keyboard-producing side buttons, pause on focus loss, save/restart, edit, JSON import/export, and CSV export. Hardware-specific buttons need testing with the actual mouse.

The mouse reader follows Microsoft's [RAWMOUSE](https://learn.microsoft.com/windows/win32/api/winuser/ns-winuser-rawmouse) and [Raw Input](https://learn.microsoft.com/windows/win32/inputdev/about-raw-input) documentation. Keyboard signals use foreground Windows messages so software-generated mappings can also be detected.
